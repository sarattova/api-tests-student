# API-тесты TestBoard

Проект проверяет создание объявлений, поиск, фотографии, список своих объявлений и избранное через [TestBoard API](https://testboard.avito.com/swagger/index.html). Тесты отправляют настоящие запросы на тестовый сервис.

## Подготовка

1. Установите [Go 1.25.1 или выше](https://go.dev/doc/install), [Git](https://git-scm.com/install/) и при необходимости редактор Go (например, [VS Code](https://code.visualstudio.com/)).
2. Склонируйте **свой публичный fork**: `git clone https://github.com/<ваш-логин>/api-tests-student.git`. Перейдите в папку `api-tests-student`.
3. Установите зависимости: `go mod tidy`.
4. Создайте в корне проекта файл `.env.override`:

```dotenv
TEST_LOGIN=логин_основного_аккаунта_TestBoard
TEST_PASSWORD=пароль_основного_аккаунта
TEST_OTHER_LOGIN=логин_второго_аккаунта_TestBoard
TEST_OTHER_PASSWORD=пароль_второго_аккаунта
DEBUG=false
```

Нужны **два разных аккаунта TestBoard**. Если второго ещё нет, создайте его через `POST /auth/register` в [Swagger](https://testboard.avito.com/swagger/index.html). Основной пользователь добавляет объявления в избранное; второй владеет этими объявлениями и удаляет их. Аккаунты должны существовать до запуска тестов, но заранее создавать объявления не нужно. Значения `TEST_*` относятся к TestBoard, а не к GitHub. Адрес API уже задан в файле `.env`. Файл `.env.override` внесён в `.gitignore`: не добавляйте его или пароли в коммиты.

## Запуск

Из корня репозитория:

```bash
go test -p 1 -count=1 -v ./...
```

`-p 1` запускает пакеты последовательно: при нескольких одновременных запросах тестовый сервер иногда блокирует их и возвращает не-JSON ответ. `-count=1` отключает кеш результатов Go, поэтому команда действительно проверяет каждый прогон.

Отдельные части:

```bash
go test -count=1 -v ./tests/scenarios/advertisementCreation/
go test -count=1 -v ./tests/scenarios/favorites/
```

Для проверки повторяемости запустите общую команду три раза. Каждый тест создаёт своё объявление с уникальным названием и удаляет его при завершении, даже если проверка упала. Тесты не требуют заранее созданного объявления «Носки».

Для вывода HTTP-запросов и ответов можно временно установить `DEBUG=true` в `.env.override`. Такой вывод может содержать токены авторизации; не публикуйте его.

## Что проверяется

- Создание объявления со всеми полями и фотографией; совпадение данных при получении по ID, поиск по полному названию и наличие фотографии в `GET /advertisements/{id}/photos`.
- Ошибки создания: пустое название и описание, отрицательные цена и количество, слишком длинное название, отсутствие фотографии, отсутствие или неверность токена. Проверяются статус и сообщение API.
- Поиск по разным частям названия и регистрам букв.
- Избранное: добавление, появление в списке, удаление из списка и исчезновение после удаления самого объявления.
- Ошибки избранного: пустой и несуществующий ID, отсутствие или неверность токена, повторное добавление и добавление своего объявления.

В актуальном [Swagger TestBoard](https://testboard.avito.com/swagger/index.html) получение и удаление одного объявления используют `GET/DELETE /advertisement?id=<id>`. Путь `/advertisement/{id}` в формулировке лабораторной не соответствует этой спецификации. Для фотографий используется путь с `{id}`.

## Линтер

Установите [golangci-lint](https://golangci-lint.run/docs/welcome/install/local/) и запустите в корне проекта:

```bash
golangci-lint run
```

Результат должен быть `0 issues`. Изменения для ревью отправляются прямо в `main` своего fork-репозитория: `git push origin main`. Отдельный pull request не требуется.
